# Contribuir a Gutierrez Systems

Este archivo define lineamientos generales para los repositorios que no tengan una guía más específica.

## Flujo esperado

1. Crear una rama desde `main`.
2. Mantener cambios pequeños y coherentes.
3. Ejecutar las validaciones disponibles del repositorio.
4. Abrir un Pull Request con problema, solución, impacto, riesgos y validación.
5. Fusionar únicamente después de revisión y checks aplicables.

## Convenciones

Se prefieren mensajes compatibles con Conventional Commits, por ejemplo `feat:`, `fix:`, `docs:`, `test:`, `refactor:` y `chore:`.

## Seguridad

No incluir secretos, credenciales, archivos `.env` reales, datos personales o documentos de clientes y empleados sin autorización y controles adecuados.

## Documentación

Cada producto mantenido debe explicar su propósito, arquitectura básica, configuración local, variables de entorno requeridas sin valores reales, comandos de validación, estrategia de despliegue y limitaciones conocidas.

Las reglas específicas de cada repositorio prevalecen sobre esta guía general.
